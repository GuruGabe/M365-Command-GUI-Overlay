10-23-2026  v0.9  BROWSER VERSION; PASSWORDS NEVER REACH A FILE.
                  - New m365_web.py: M365GUI in a web browser (like GAMGUI's
                    gam_web.py), for a computer with no desktop (e.g. Azure
                    Cloud Shell, a server over SSH) or for anyone who prefers
                    a browser. Same tasks, search, Favorites / Recent,
                    "Signed in as", Pick... lists, Save results to (as a
                    download), Run for each CSV row (upload the CSV), and all
                    four guided workflows with their questions; the new
                    password of the compromised-account response opens in its
                    own window, never in the output.
                    Run: python3 m365_web.py, then open http://127.0.0.1:8080.
                    It listens on this computer only, needs a secret token
                    only its own page knows, accepts JSON only and checks
                    the Host name; the server builds every command itself
                    and refuses a destructive task the page did not confirm.
                  - SECURITY FIX: a password typed into Reset password,
                    Create user or Check a password was written to the
                    session log (Logs\M365GUI_*.log) and to the Run for each
                    CSV row record. Both now show ******** instead; the
                    window still shows what was typed.
                  - The Remove ALL guest users workflow moved into
                    m365_workflows.py so both versions run the same steps
                    (still: type DELETE to go ahead).
                  - Tests: tests\test_v09_web.py (a real local server and a
                    stand-in m365), tests\test_v09_redact.py.
10-23-2026  v0.8  GUIDED STAFF HAND-OFF AND COMPROMISED ACCOUNT RESPONSE.
                  - Users > Staff hand-off - someone is leaving: saves a
                    record of their groups and licenses first, asks once,
                    then (only the steps set to Yes) blocks sign-in, signs
                    them out, copies their OneDrive files to their manager
                    while the license still exists, sets an automatic reply,
                    removes them from their groups and removes their
                    licenses. Removing licenses (their mailbox is deleted 30
                    days later) is No by default. A failed step is reported
                    and the others still run.
                  - Security > Compromised account response: blocks sign-in,
                    signs the account out everywhere and sets a new random
                    password (shown once in its own window - never in the
                    output or any log), then saves evidence (recent sign-ins,
                    MFA methods, groups, licenses) and NEXT-STEPS.txt with
                    what to do next in the admin centers.
                  - Both keep their records in the Records folder (in the
                    settings folder).
                  - Tests: tests\test_v08_workflows.py (also checks every
                    command they run against the CLI's docs).

10-22-2026  v0.4  ONEDRIVE: COPY A USER'S FILES TO ANOTHER USER; NO SHELL.
                  - New OneDrive section:
                    - 'Copy a user's OneDrive files to another user' - for
                      a leaver: copies everything into a new folder in the
                      recipient's OneDrive. Nothing is removed from the
                      leaver; same-name files are renamed, never
                      overwritten. Shows the file count and size, asks
                      Yes/No once, then counts the files that arrived and
                      saves a CSV record (Logs\OneDrive-Copy_*.csv). The
                      admin is made site admin of both OneDrives for the
                      run; only the access M365GUI added is removed again
                      (or kept, if chosen). Stop ends it after the current
                      item and still removes the access.
                    - 'Find a user's OneDrive address'.
                  - SECURITY FIX: commands no longer go through cmd.exe.
                    m365.cmd passed every value to cmd.exe, which treated
                    '&' (and | < > ^) as the start of ANOTHER command - a
                    value 'a&echo.x' ran 'echo.x' (checked live 10-22-2026).
                    A display name, group or file/folder name with '&'
                    could run something on the admin's PC. M365GUI now
                    starts node with the CLI's own script directly. On an
                    install where that script is not found it still uses
                    m365.cmd but refuses such values.
                  - No console window flashes up for each command, and a
                    question from the CLI can no longer leave a task
                    hanging (commands get an empty input).
                  - Tests: tests\test_onedrive_transfer.py (fake m365, 31
                    checks), tests\test_invocation.py.
08-07-2026  v0.3  DEPLOY FIX: the build no longer ships the Tcl encoding
                  files (_internal\_tcl_data\encoding\*.enc). Endpoint
                  security (e.g. CrowdStrike) blocks the .enc extension - it
                  looks like ransomware output - so copying the app to other
                  machines failed with "permission denied" for every account.
                  Tcl 9 keeps these encodings inside the DLL and falls back
                  to them, so extract_tcl.py now removes the loose .enc files.
                  Verified 0 .enc shipped and the app runs normally.
